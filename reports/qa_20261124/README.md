## 本轮发现了什么

以下是实际复现后修复的重点，初次失败文件保留在各专项报告中。

- **跨身份旧数据残留**：HR01已获授权的响应被延迟，切换到HR02或员工后，仍可覆盖列表或弹出旧详情。修复了前端响应身份隔离；没有把这个问题误报为服务器对象权限被绕过。
- **知识编辑无法正常逐字输入**：标题只留下首字母，后续键击因焦点被重设而丢失。原先使用fill()的测试没有发现，改用真实按键复现并修复。
- **错误条款及坏规则**：问题命中制度第二节却返回第一节；非法材料规则能发布，随后员工清单500。现在按条款检索，并在草稿阶段校验结构。
- **统计可能漏掉不好的结果**：请求重开后已有1分“未解决”反馈被移出统计；自报深圳的员工首次失败提交也可能不进入深圳HR看板。现在保留真实反馈机会，并统一请求、尝试、咨询和反馈的组范围。
- **预览与确认不一致**：HR或员工改变业务条件后，旧预览仍可直接创建请求；现要求重新预览。补交日期改按上海自然日校验，前端统计日期也明确带+08:00。
- **其他可复现边界**：Unicode令牌导致500、会话到期端点、字符串确认被转为true、同刻时间线乱序、模态焦点逃逸、低对比度、无效筛选显示旧指标、并发冲突无法保留输入刷新。
- **远程等待拖住整库**：慢模型调用发生在SQLite写事务内。现将外部等待移出锁，返回前再核对当前身份、条件和政策；等待中撤回的制度不会泄露到返回结果。
- **旧依赖包含公开公告匹配**：更新并锁定FastAPI0.165.0、Starlette1.10.0、pytest9.2.0、Vite6.4.5，升级后完成总回归和再次审计。

## 为什么这一轮更有检验力

- 角色×对象×动作×状态决策表覆盖拒绝路径和失败无副作用。
- 2,000组范围组合用独立点集枚举判断交集；350个请求、700条尝试用独立标量计算复核指标，打乱顺序仍不变。这些是夹具规模，不另算测试用例数量。
- 通过线程事件和拦截响应控制竞态，不靠任意睡眠碰运气。
- 浏览器验证“已建单但响应丢失”的网络重试，并从数据库结果核对幂等。
- 320/390宽度、正反Tab、Escape、逐字输入实际运行；22个文字/状态对比度样本最终5.65–6.46:1。没有宣称全站无障碍认证。
- 版本指纹、初次失败、最终JSON/XML均可追溯。[测试计划](test_plan.md)和[C1–C19需求追溯](traceability.md)说明了方法和范围。

## 性能口径

隔离SQLite从72个种子请求开始，单Uvicorn进程、默认离线模式、真实回环HTTP。450个操作中，建草稿并确认算一次业务操作但包含两次HTTP；另有16路同键重试及启动/恢复探测。

最终并发8时P95：列表123.33ms、咨询230.03ms、草稿+确认149.75ms、分析436.40ms。所有场景最大P95为436.40ms，没有意外HTTP错误。机器同时用于开发与其他测试，样本较小，没有长稳测试，不能外推企业人数、生产吞吐或业务收益。

## 复现

在仓库根目录执行（依赖已按README安装）：

```bash
.venv/bin/python -m pytest backend/tests -q
.venv/bin/python scripts/evaluate.py --output-dir reports/qa_20261124
npm --prefix frontend run build
cd frontend
npm exec -- playwright test --config playwright.qa.config.ts
cd ..
.venv/bin/python scripts/qa_load.py
.venv/bin/python scripts/qa_dependencies.py
```

最后一项需要访问公开OSV服务；其余不需要模型密钥。浏览器使用本机Chrome或已安装的Playwright Chromium。脚本版本见`scripts/test_professional.sh`；测试端口8002/8003必须空闲。
