# 五阶段实施记录

## 阶段一：业务与数据骨架

完整阅读任务书并检查空仓库、父级约束、Python/Node/npm、空闲端口和联网条件。采用指定 FastAPI + React/TypeScript，SQLite 文件持久化。建立固定演示身份、会话、角色/组/对象权限，以及 16 条制度、72 个合法流转历史请求。PRD、权限矩阵和数据字典在 docs 中；种子数据没有真实人员信息。

## 阶段二：最小办理闭环

实现预览草稿→员工确认→HR 接单→补问/IT 任务→HR 处理结果→员工确认/重开。后端按事项检查完成条件，独立跟踪材料、审批和任务。幂等重试、首次缺项提交持久化、行版本冲突、事务回滚、取消联动和持久化均有实测覆盖。发现并修复材料标签与结构化编码不一致、草稿编辑缺少并发校验等问题。

## 阶段三：知识与咨询

从服务端身份和结构化自报条件确定范围，按计划入职日过滤，检查全部适用候选冲突，再做中文字符 n-gram TF-IDF。引用指向稳定版本；发布时拦截集合部分交集，新旧区间事务衔接，原回答仍可追溯。针对无依据但共享少量常见字符的查询补充了证据词门槛。查询不使用验收集标签或整句映射。

## 阶段四：运营与评价

指标直接从事件/工单/尝试/反馈计算，明确时间窗、样本和分母；图表可追溯，demo/manual/test 隔离。30 条开发任务、60 条公开合成验收任务分文件，真实执行结果在 reports 中。首次验收 59/60 的唯一失败是冲突夹具多插入解码别名字段，修正评价器后 60/60；原报告保留，没有把失败隐藏成应用成功。人工语义复核、访谈及探索性用户测试尚未开展。

## 阶段五：可选模型与交付

默认无 Key 离线运行。远程归纳适配器只接收获准片段，验证输出结构与引用；缺配置、超时和非法输出回退，不参与审批、身份或业务写入。交付锁定依赖、初始化/重置脚本、Windows/macOS/Linux 启动步骤、演示账号、五分钟脚本和实际自动测试记录。真实模型服务与跨平台实机验证未运行。
