# 指标字典与复算

`GET /api/analytics/summary` 返回定义、样本数、窗口、范围、分子与分母；点击指标可从 `/details?metric=...` 追溯原始行。`/export` 使用同样的服务器权限，并转义 CSV 公式开头。员工和 IT 无分析接口访问权。HR 仅查看其组，管理员查看模拟企业。

默认窗口最近 30 天，`start` 含起点、`end` 不含终点；没有历史时点回放功能，`as_of` 是当前可注入系统时钟。API 的无时区日期查询值按 UTC 解析；UI 日历筛选显式发送 Asia/Shanghai 的 `+08:00` 午夜边界，开始日期包含、结束日期不包含，避免跨日八小时误差。默认来源 `demo`，可独立选择 `manual`/`test`，不混算。

|指标|分子、分母或计算|注意|
|---|---|---|
|咨询数|窗口内唯一 conversation_id 数|同一会话消息条数另列，不等同员工人数|
|类别|question_submitted.category 分组|未知保留 OTHER|
|一次提交完整率|首次尝试 valid 的草稿数 / 有首次提交的草稿数|失败且没有 case_id 也入分母；同一草稿第二次成功不能改写首次失败|
|首次人工响应小时|窗口内建单、已有首次 HR 公开回复的时间差均值|没有公开回复另列等待小时；内部备注、分派及自动收件不计|
|解决时间|最新解决在窗口且当前 resolved/closed，从原创建到最新解决的平均小时|另列所有未解决请求年龄，不删除未完成请求造成幸存偏差|
|按期解决率|窗口内已到期、非取消、当前 resolved/closed 且最新解决不晚于 due_at / 窗口内已到期非取消请求|超期解决、重开未解决都不计分子；尚未到期不纳入|
|员工确认完成|窗口内建单、当前 closed 请求数|已回复/已解决不等于确认|
|取消数与重开次数|窗口内建单请求的取消数/累计重开次数|取消不计解决；重开不重设 SLA|
|反馈率|应反馈对象的有效回复数 / 应反馈对象数|窗口内有答复的会话一次、出现最新解决事件的请求一次（随后重开仍保留反馈机会与已有评价）；未反馈不代表满意|
|容易程度|有效反馈 1–5 分均值|与“已解决/未解决/不确定”分别显示|
|重复联系|同一 case_id 的 employee_message(kind=progress_inquiry) 事件数|不是重开率|
|材料缺项排行|窗口内新建补交申请 structured_fields.missing_item 分组|反映请求频次，不是未收齐人数；与首次提交表单缺字段分开|
|知识缺口|无依据、条件缺失、范围冲突等结构化原因|提供原始事件，建议仅是待审核草稿|

分母为零返回 `null`，前端展示“暂无可计算样本”。普通计数为 0 表示实际没有记录，不代表业务改善。参数默认材料申请 48 小时、账号设备 24 小时、一般入职 48 小时，均是虚构 SLA。等待员工仍按自然小时计时，无工作日历。

## 独立夹具

`backend/tests/test_metrics.py` 不读取看板预计算值：构造 4 个已到期非取消请求（按期、迟到、未解决、重开），预期按期率 1/4；构造首次缺项再成功与首次完整两个草稿，预期完整率 1/2；无人工回复不混成 0 小时。再改变源记录，确认指标随之变化。

指标是对当前数据库模拟记录的描述，不能用于证明 HR 耗时降低或用户体验改善。真实收益待探索性用户测试及企业试点验证。

## 专业测试后的范围修正

请求相关尝试与反馈按请求实际分派组过滤；未建单的首次失败尝试按草稿确认的查询城市归属；未提供城市时沿用广州 HR 的演示默认接入规则。咨询事件保存当时的公司、负责组与查询条件快照，避免自报地点正确匹配深圳制度但在深圳看板漏计。旧种子事件没有范围快照时使用已验证员工资料，无法从旧数据重建未保存的自报信息，不追溯编造。
