# 制度检索、版本与可选模型

制度均为入职服务模拟内容。16 条文章/版本由 `backend/app/knowledge.py` 的 `seed_knowledge` 初始化，含广州旧/新相接版本、深圳未来版本、HR 内部说明及未发布草稿。制度规则中的 `required_fields` 等字段与工单校验共用 `RULES`，可读的规则说明从这些字段生成。

先验证服务端身份，再合并已验证资料及仅限缺失字段的自报条件。自报字段不能更改公司、角色或已验证字段。所有日期按计划入职日匹配，不以今日代替缺失日期；可见角色、公司、城市、类型、已发布状态、发布时间及左闭右开有效期均在检索前过滤。候选全集先按 `policy_key` 检查重叠，再进入排序；因此低排名的冲突版本也会转人工。

本地基线为中文字符 1–3 gram TF-IDF、余弦相似度，阈值 0.10，最多返回 3 个版本。明确的补交/账号设备事项有 0.10 的结构化类别匹配加分；同时要求共享至少一个非通用二元字符片段，避免只有“入职”“广州”“领取”等词就认为证据充分。参数在开发与边界回归阶段记录，运行代码不读取验收标签。分数只用于检索，不作为正确概率。新增获准发布的文档直接参与检索，无须增加整句问题映射。

文章命中后还会按当前问题对章节排序，引用最相关章节，避免总是展示第一条。片段以 `section-N` 为稳定锚点；引用包含文章版本 ID、版本、条款、原文、原文 SHA256 和适用范围。当前回答与历史回答保存在 `knowledge_answers`。引用详情和历史回答接口都会再次检查当前权限；范围变化后，历史缓存正文不直接返回，保留审计记录并提示重新查询。过期/撤回文档只有确实引用过它的员工可以作为只读历史材料打开。HR 管理员可审阅公司知识版本。当前检索不读撤回或过期版本。第一版直接查询数据库、不维护缓存，发布/撤回之后下一次请求即反映更新。

发布是事务操作。相同制度编号若城市集合、类型集合及日期区间均相交，则拒绝；`*`/`全部` 展开为全集。通过 `replaces_id` 衔接版本时，要求相同范围与编号，把旧版本结束日改为新版本开始日，随后再次验证无重叠。如果失败，旧版本的日期修改一同回滚。历史内容不可编辑。草稿可编辑并有 `row_version`，发布需管理员且审核人不同于草稿作者。

默认 `LLM_MODE=offline`。可选远程适配器使用环境配置的 `LLM_ENDPOINT`（完整 chat/completions 地址）、`LLM_MODEL`、`LLM_API_KEY`，8 秒超时、零次重试。只有已有依据的 `answer` 会调用远程服务。输出需通过 Pydantic schema，并且引用 ID 必须来自本次合法片段。缺配置、超时、非法 JSON 或虚构引用都退回 `offline_fallback`。

远程措辞作为单独的 `remote_summary_draft` 返回，**不会替换可核查的本地制度答案**；模型没有工具、SQL 或业务写入能力。审批、身份、工单操作及完成条件始终由本地后端执行。前端目前展示本地可核查答案；远程草稿可在 API 中检查。真实远程服务尚未运行；四种故障使用模拟响应测试，不算真实模型成绩。

已知限制：字符匹配仍可能漏掉深层语义改写，不能保证发现不同制度之间的任意语义冲突。自动检查验证范围、引用有效性和明确断言，不代表人工语义质量评估。人工事实正确性、无额外主张和下一步可执行性仍待复核。

## 并发与结构校验

远程等待在数据库事务之外执行。返回后以短事务再次核对会话归属、当前员工资料、制度状态和引用范围；等待期间撤回或修改了依据时重新生成本地结果，不展示已失效的远程草稿。材料规则的每一项必须有非空字符串编码与名称，编码不得重复；错误 JSON 条目返回可识别的校验错误，不能发布后让清单接口崩溃。制度发布时间比较使用实际时刻，兼容带时区偏移的导入 ISO 时间。
