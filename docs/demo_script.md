# 五分钟演示脚本

演示前按 README 启动并初始化数据。浏览器员工身份 emp01（广州正式员工）；HR hr01；IT it01；管理 admin01。默认离线，不需要 API Key。所有人物、政策、材料和通知均为本地模拟。

|时间|操作|讲述重点|
|---|---|---|
|0:00–0:40|打开员工页，说明演示标签|选题来自公开资料与可实施性判断；没有真实访谈或收益数据。展示的是完整服务流程，不是聊天界面替代一切|
|0:40–1:30|查询“入职需要准备什么，在哪里报到”，点开引用|条件来自服务端资料，按计划入职日匹配；显示制度名称、版本和条款。切换 emp04 可对比深圳实习生|
|1:30–2:30|选缺件申请，填写“入职信息表”、预计补交日，预览确认；切 HR 接单、补问或批准延期|建单必须确认；补交审批完成后材料仍显示缺失。切员工确认结果，后续真正补交才改变元信息|
|2:30–3:20|创建账号设备异常请求，再查询“我的账号设备准备进度”；HR 在该请求创建 IT 子任务，IT 完成|主责始终是 HR；IT 看不到材料详情。未完成必需任务不能解决；任务文案“演示任务已完成”不代表真实账号|
|3:20–4:00|问“我的绩效奖金是多少”；尝试员工访问另一员工请求|无依据明确转人工，不能从聊天伪造角色。历史引用与当前适用版本分开|
|4:00–5:00|管理身份打开服务分析，点首次完整率或缺项详情；展示实际测试报告|缺项拦截的首次提交也计分母；指标可追溯事件。合成自动筛查与人工语义复核分开，后者待执行；下一步邀请 HR 与员工做探索性测试|

若当前员工已有同类未结束请求，先展示已有记录；确有新的演示事项时勾选明确新建，不反复点击制造重复请求。录屏前可按 README 的显式确认命令重置演示数据，避免旧操作干扰。五分钟展示可利用预置历史请求，不需要现场等待 SLA 到期。
